# Registered v1.1 Scrambled-Null Transform (Amendment)
**Date:** 2026-11-11  
**Status:** Post hoc room decision and fix; registered rule for v1.1. No rerun has been done yet.

---

## 1. Background & Root Cause Analysis

In the frozen v1.0.0 pipeline (`exosearch.nulltest.transform("scramble")`), the scrambled null test operated by cutting the quality-masked light curve into approximately 1-day blocks of cadences and permuting those blocks globally across the light curve before gap-edge trimming and detrending:

1. **Permutation across gaps:** Blocks were shuffled indiscriminately across data segments and spacecraft orbit gaps.
2. **Gap-edge ramp translocation:** Thermal ramps and scattered light features occurring immediately before and after orbit downlinks / data gaps were relocated into clean, unperturbed sections of the light curve.
3. **Step-edge artifacts:** Discontinuous edges between permuted blocks created artificial box-step dips.

As observed in Sector 106, this inflated the scrambled null test statistics ($S^*$), severely distorting the null distribution and interfering with the two-sample null comparison (TOST gate) against the flipped null.

---

## 2. Registered v1.1 Scramble Rule (2026-11-11)

On 2026-11-11, the room decided on the exact scramble rule for v1.1 null testing:

1. **Input light curve & gap-edge trimming:**
   The input is the quality-masked light curve ($Q = 0$, finite flux and errors). Before any scrambling occurs, `lightcurve.gap_edge_mask` is applied using the exact parameters of the detrender (`gap = 0.5` d, `trim = 0.3` d). All cadences within 0.3 d of gaps $> 0.5$ d or sector endpoints are dropped upfront so gap-edge ramps cannot enter the scrambling pool.

2. **Segmentation:**
   The remaining cadences are split into contiguous segments at all gaps $> 0.5$ d.

3. **Segment cyclic rotation:**
   Each segment's flux and flux error vectors are rotated together by an independent random cyclic integer offset drawn from `numpy.random.default_rng(seed)`:
   $$\text{offset}_i \sim \text{Uniform}\{0, N_i - 1\}$$
   Time stamps stay strictly fixed. Samples never cross a segment or orbit gap boundary.

4. **Short segment fallback:**
   A segment is considered too short for a meaningful cyclic rotation if its duration is shorter than $3\times$ the longest trial duration in the search grid ($3 \times 0.25\text{ d} = 0.75\text{ d}$):
   - If the segment duration is $< 3 \times D_{\max}$ but contains at least one contiguous block of length $\ge 3 \times D_{\max}$, shuffle the segment in contiguous blocks of length $\ge 3 \times D_{\max}$.
   - If the entire segment is shorter than one such block (duration $< 3 \times D_{\max}$), leave it unrotated and record the scheme as `'unrotated'`.

5. **Provenance recording:**
   The per-segment offsets and applied scheme (`scr_offsets`, `scr_scheme`, `scr_schemes`, `n_segments`) are returned by `exosearch.v11.scramble.segment_rotate` and recorded in the v1.1 pipeline task output row.

6. **Configuration parameters:**
   All parameters are declared under the `"scramble"` section of `configs/v1.1.json`:
   - `gap_d`: $0.5$
   - `gap_trim_d`: $0.3$
   - `block_duration_multiplier`: $3.0$
   - `longest_trial_duration_d`: $0.25$

---

## 3. Status

This rule is a registered post hoc fix for the v1.1 pipeline. No rerun of Sector 70 or Sector 106 has been performed yet with this new scrambled-null transform. v1.0.0 code (`exosearch/nulltest.py`) remains frozen byte-for-byte to maintain exact reproducibility of v1.0 products.
