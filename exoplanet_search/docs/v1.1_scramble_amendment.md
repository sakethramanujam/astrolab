# Registered v1.1 Scrambled-Null Transform (Amendment)
**Date:** 2026-11-11  
**Status:** Post hoc Scientist ruling and revision; registered rule for v1.1. No rerun has been done yet.

---

## 1. Background & Root Cause Analysis

In the frozen v1.0.0 pipeline (`exosearch.nulltest.transform("scramble")`), the scrambled null test operated by cutting the quality-masked light curve into approximately 1-day blocks of cadences and permuting those blocks globally across the light curve before gap-edge trimming and detrending:

1. **Permutation across gaps:** Blocks were shuffled indiscriminately across data segments and spacecraft orbit gaps.
2. **Gap-edge ramp translocation:** Thermal ramps and scattered light features occurring immediately before and after orbit downlinks / data gaps were relocated into clean, unperturbed sections of the light curve.
3. **Step-edge artifacts:** Discontinuous edges between permuted blocks created artificial box-step dips.

As observed in Sector 106, this inflated the scrambled null test statistics ($S^*$), severely distorting the null distribution and interfering with the two-sample null comparison (TOST gate) against the flipped null.

---

## 2. Revised v1.1 Scramble Rule (Scientist Ruling 2026-11-11)

On 2026-11-11, the Scientist ruled to revise the segment rotation rule and supersede the earlier fallback proposal:

1. **Input light curve & gap-edge trimming:**
   The input is the quality-masked light curve ($Q = 0$, finite flux and errors). Before any scrambling occurs, `lightcurve.gap_edge_mask` is applied using the exact parameters of the detrender (`gap = 0.5` d, `trim = 0.3` d). All cadences within 0.3 d of gaps $> 0.5$ d or sector endpoints are dropped upfront so gap-edge ramps cannot enter the scrambling pool.

2. **Segmentation:**
   The remaining cadences are split into contiguous segments at all gaps $> 0.5$ d.

3. **Segment cyclic rotation:**
   Rotate **every** segment, regardless of length, by its own independent random cyclic integer offset drawn from `numpy.random.default_rng(seed)`:
   $$\text{offset}_i \sim \text{Uniform}\{0, N_i - 1\}$$
   Flux and flux error vectors move strictly together, time stamps stay fixed, and no sample crosses a gap boundary.

4. **Removal of fallback:**
   The Scientist ruling removes the block-shuffle fallback and the leave-unrotated path entirely. A 1-sample segment trivially rotates by 0. The configuration parameters `block_duration_multiplier` and `longest_trial_duration_d` have been deleted.

5. **Provenance recording:**
   The per-segment offsets and scheme (`scr_offsets`, `scr_scheme='segment_rotation'`, `n_segments`) are returned by `exosearch.v11.scramble.segment_rotate` and recorded in the v1.1 pipeline task output row.

6. **Configuration parameters:**
   The parameters in `configs/v1.1.json` under `"scramble"` are:
   - `gap_d`: $0.5$
   - `gap_trim_d`: $0.3$
   - `exclude_hosts_file`: per-sector path mapping to host exclusion tables (e.g. `"70": "configs/scramble_exclude_s0070_2026-11-11.csv"`).

## 3. Planted Signal Measurement & Conclusion

Using the real Sector 70 cadence and gap structure (`tests/fixtures/s0070_cadence.npz`), white noise plus mild red noise, and a box transit train injected at $P = 1.0, 3.0, 6.0$ d (each with raw unscrambled significance $> 20\sigma$), the phase-folded depth significance at injected $P/t_0$ after scrambling across 10 random seeds yielded:

```
P      median_sigma   max_sigma    n_seeds 
1.0    3.69           7.70         10      
3.0    1.82           7.23         10      
6.0    0.93           7.82         10      
```

### Conclusion Regarding Periodic Transit Preservation
With the real Sector 70 cadence (~8.3 d and ~10.9 d segments separated by a 4.01 d gap), cyclic rotation keeps the periodicity intact inside each segment. Consequently, cyclic rotation cannot be relied upon to erase real transits (max sigma stays above $3\sigma$ across seeds at every period, reaching up to $7.82\sigma$). This empirical result is accepted rather than tuned away. To prevent genuine planetary or eclipsing binary transits from polluting the scrambled null distribution, known hosts must be explicitly excluded.

## 4. Host Exclusion Rule

To ensure the scrambled null distribution is not contaminated by preserved coherent transits of known astrophysical systems, the pipeline implements **Host Exclusion**:
1. **Catalogues & Snapshots:**
   - **ExoFOP TOI Table:** Snapshot of 2026-11-10T21:05Z (all TOI hosts, any disposition).
   - **TESS Eclipsing Binaries:** Prsa et al. 2022 (VizieR J/ApJS/258/16, fetched 2026-11-10T22:58Z).
2. **Sector 70 Exclusion Table:**
   - Saved as a fixed list in `configs/scramble_exclude_s0070_2026-11-11.csv` (SHA256: `afa7c0122f3a1254177c87c85cbe7108acb9371c0b477dbf238615f03837cd97`).
   - Contains 285 unique TICs (222 TOI hosts, 67 TESS EBs, 4 overlapping).
   - Fixed list with strictly no runtime refresh.
3. **Pipeline Manifest Filtering:**
   - During manifest building (`exosearch.v11.run.build`), any TIC listed in the exclusion table has its `scramble_r*` tasks skipped. Real search and `invert` tasks for these TICs remain completely unchanged.
   - The exclusion file name and its SHA256 digest are recorded in the run provenance.
