# v1.1 implementation plan (planning only; no v1.1 code or runs yet)

v1.0.0 stays frozen (config_hash 80ffc7f29943). v1.1 is a new pipeline version with its own config hash, nulls and
injections; nothing from v1.1 is mixed into v1.0 products or the interim layer. Findings behind each item:
`docs/v1.1_odd_even_secondary.md`.

## Statistic

1. **Exact box depth in S.** S from the box depth at each (P, D, T0) (compute_stats estimator), not the BLS
   fast-method depth; at minimum, refine the top-k fast peaks per star with the exact depth before taking the max.
2. **Out-of-transit term.** S normalised with sigma_D·sqrt(1 − D/P) restored, so white-noise S follows the
   joint-Gumbel calibration (N_eff ≈ 4.3e4 per star).
3. **Beta treatment inside the statistic**, chosen by the registered rule (`docs/preregistration/beta_treatment.md`);
   provisional choice c (floor at 1 − 2·sigma_beta), others as sensitivity rows.
4. **Pulsator prewhitening** before detrending: iterative sinusoid removal above ~5 c/d (stop at amplitude S/N < 4
   or 20 terms), frequencies and amplitudes logged per star; sigma_w measured after prewhitening.
   **Comb guard (RF Engineer):** before removing a peak at f, check the power at 2f and 3f. If the f, 2f, 3f
   amplitudes match the harmonic ladder of a box (periodic transit) of plausible duration (1–6 h at P = 1/f or an
   integer multiple), flag the peak as `comb` and do not remove it. Logged per star (`prewhiten_comb` flag).
5. **odd/even and secondary:** significance plus relative-depth rule (reject only when the difference is significant
   and > the registered fraction of the primary depth), validated on injections.
6. **Momentum-dump veto:** epochs within 0.1 d of a dump flagged; reject at ≤ 2 epochs, warn otherwise; N_tr recounted.

## Validation before any v1.1 re-search (injections only, then nulls; never candidates)

* **Prewhitening + comb guard on injections**, binned by duration and period, with USPs (P < 1 d) and 1–2 h
  durations broken out. Report recovery rate and recovered-depth bias (depth_rec/depth_inj) with and without
  prewhitening (and with the comb guard on/off). If prewhitening costs recovery or biases depth in any bin (USP
  harmonics fall above 5 c/d for P < 0.2 d; 1-h boxes put power near 24 c/d), lower the cutoff or protect transit
  harmonics, and re-validate. Uses the v1.0 injection hosts and seeds on S70 (re-injected, v1.1 code).
* Beta treatment selected on the v1.0 interim nulls (flipped + scrambled r0) and injections.
* Every headline number (S*, completeness, false-alarm rate, candidate counts) reported with and without the
  star-quality cut, on the site and in the docs.

## Runs (after validation; launch decision and compute allocation by the owner)

Fresh v1.1 nulls at the registered sizes (`docs/preregistration/s_star_freeze.md`: full flipped + 3 scrambled per
sector, S70 and S106), v1.1 injections (same spec as injection_v1), then the v1.1 real re-search. Frozen S* comes
from these only.

## Multi-host execution

* Extra workers (an 18-core ARM machine and an x86 Linux machine) run the same float64 CPU code at the **pinned v1.1
  commit** with a **lockfile** (exact package versions, same BLAS threading = 1).
* **Split by TIC ID**: each star's real, null and injection runs stay on one host.
* **Gate before any merge:** a shared batch of ~200 stars run on every host must give the same best (P, D) and S
  equal to within 1e-6 (absolute) across hosts. Any failure blocks the merge for that host.
* Rows carry an opaque `host_id` (h1, h2, h3), `arch` and `lib_versions`; never real hostnames. The host_id mapping
  lives outside the repo.
* GPU or float32 BLS is a **separate statistic** with its own nulls and injections, never mixed into S*.

## Compute and ETA

The lane cap (`docs/interim_lane_cap.md`) frees 3 cores when labels finish (~20:30 PST Nov 10; the queued S105
null and S70 real subsamples take them first, ~5 h), 3 more when injection run 1 for S70 ends (~22:30 PST), and 6
when scrambled r0 ends (~05:00 PST Nov 11). From then 12 batch cores are free. At v1.0 throughput (~12 stars/min per
worker) a v1.1 flipped null for S70 + S106 (25.8k stars) takes ~3 h on 12 cores, three scrambled realizations ~9 h,
12k injections ~1.5 h, so ~14 h of runs once v1.1 code and the injection validation (~1 day) are done: earliest
frozen S* around Nov 13, subject to the owner's compute decision and any extra hosts passing the gate.

## Registered duration-grid cap (physical duty-cycle limit)

* Per star, cap the trial durations at a maximum duty cycle q_max(P, rho_*) = 3 × the circular, central-transit
  duty cycle from the TIC density: q_circ = T14/P ≈ (1/π)·(3π / (G·rho_* ·P²))^(1/3) (for b = 0, Rp ≪ R_*),
  so D_max(P) = 3·q_circ·P. Stars without a TIC density get q ≤ 0.1. Following Hippke & Heller (2019, A&A 623, A39;
  TLS), which grids durations by the stellar density.
* Applied identically to the real search, the nulls and the injections (same function, same TIC inputs).
* Consequence: fewer independent trials, so the white-noise N_eff (≈ 4.3e4 per star in v1.0) and the white-noise S*
  drop; both are re-derived for v1.1 rather than carried over.
* Expected effect on the depth audit: the D/P 0.2–0.6 null rows (2,151 of the S70 flipped null; 3.6% with
  `depth_box`/`depth` > 2× or `depth` ≤ 0, p90 1.30) are mostly short-P/long-D boxes that no star of typical density
  can produce (q_circ ≈ 0.03–0.1 for main-sequence stars at P = 0.5–3 d, so 3·q_circ ≲ 0.3). Most of them fall outside
  the capped grid; the remainder are giants/low-density stars, where long boxes stay allowed.
* **Injection design for wrong densities.** A registered subset of injections (≥ 20%) draws the transit from
  "true" stellar parameters that differ from TIC while the grid is still capped with the TIC value: unresolved
  binaries (radius inflated, density overestimated), misclassified subgiants (true density ~3–10× below TIC), and
  density errors spread log-uniformly up to and beyond 27× (duration factor ≥ 3, i.e. beyond the margin). Reported
  completeness includes these wrong-density losses, broken out by density-error factor.

## 2. Post hoc fixes (found after results were seen)

Both fixes below were found after we had seen results. They are post hoc and are labelled that way here and in
any paper.

### 2a. Scrambled null (post hoc)

* Why: the v1.0 scramble permutes ~1-day blocks of the quality-masked light curve before the gap-edge trim and
  across orbit gaps. That moves gap-edge ramps and scattered light into clean stretches, and blocks that span a
  gap create step edges. Sector 106 has two gaps (about 5.8 d of gap time, against about 2.5 d in sector 70)
  and its scrambled S* came out near 23 against about 12 to 14 for the flipped null. A handful of extreme stars
  drive that, e.g. TIC 144575712 at S = 69 (diagnosis in the 2026-11-11 null write-up). This was the main
  cause of the beta gate failure.
* Registered rule (v1.1 scramble):
  1. Start from the quality-masked light curve and apply `lightcurve.gap_edge_mask` (gap 0.5 d, same trim as
     the detrender) before scrambling. Masked cadences are dropped.
  2. Split into contiguous segments at gaps longer than 0.5 d.
  3. Rotate each segment's flux and flux error together by its own independent random cyclic offset. Time
     stamps stay fixed. No sample crosses a gap. Offsets are drawn from a seeded generator (task seed as in
     v1.0, `nulltest.seed_for`) and recorded per star in the output row.
  4. Every segment is rotated, whatever its length. There is no block-shuffle fallback and no leave-unrotated
     path (Scientist's ruling, 2026-11-11, replacing the fallback in the first draft of this rule).
  5. Host exclusion. A planted transit train on the real sector-70 cadence stays above 3 sigma after rotation at
     every tested period (P = 1, 3, 6 d, 10 seeds each: median 3.69 / 1.82 / 0.93, max 7.70 / 7.23 / 7.82).
     Rotation keeps periodicity inside each segment, so it does not erase real transits. The scrambled null
     therefore excludes a fixed list of known hosts: sector-70 targets that are TOI hosts of any disposition in
     the ExoFOP TOI table (snapshot 2026-11-10T21:05Z) or eclipsing binaries in the TESS EB catalogue of
     Prsa et al. 2022 (VizieR J/ApJS/258/16, fetched 2026-11-10T22:58Z): 285 TICs (222 TOI hosts, 67 EBs),
     `configs/scramble_exclude_s0070_2026-11-11.csv` on the implementation branch. These stars still get the
     real search and the flipped null.
  6. Parameters live in `configs/v1.1.json` (`scramble` section), so they enter the v1.1 config hash.
* Implementation: branch `agy/t1-scramble-segment-rotation` (docs/v1.1_scramble_amendment.md), merged only
  after review.

### 2b. Prewhitening (post hoc)

* Why: the first v1.1 prewhitening fix (commit `ca9d305`) was rejected on review. Its comb guard had no upper
  bound, so it protected real delta Scuti pulsations (TIC 346626001 was tagged as a comb at m = 26 to 36), and one
  false comb could block about 74% of the spectrum. Validation could not detect a filter that removes nothing.
* Validation requirement for the second pass:
  * Use NEW injection seeds only. The seeds that exposed the failure (the v1.0 `injection_v1` run-0 seeds of the
    sector-70 hosts and the `validate.py` base seed 20261110) are excluded. The new set uses base seed 20261112
    and injection runs 12 to 15 (v1.0 used runs 0 to 11). Host selection is redrawn with the new base seed.
  * Real delta Scuti stars are a pass/fail check. The list is fixed before the run: sector-70 targets whose Gaia DR3
    `vari_classifier_result` best class is a DSCT/SXPHE-type label, crossmatched from the TIC Gaia ID
    (`docs/preregistration/dsct_s70_2026-11-11/`, with the query text and date).
* All 25 listed Gaia stars are kept. Split by the dominant frequency of the sector-70 light curve (highest
  Lomb-Scargle peak of the quality-masked, normalised flux, before prewhitening): above 5 c/d counts as delta Scuti,
  5 c/d or below counts as gamma Doradus. Pass rates are reported per group and in total. With 25 stars the test is
  coarse: one star moves the total rate by 4 percentage points (more within a group).
* Prewhitening pass rule (all three must hold; fixed now, before the run):
  1. On at least 90% of the listed delta Scuti stars, the top search peak is no longer a pulsation frequency or a
     harmonic of one.
  2. Injection recovery on the delta Scuti stars is within 5 percentage points of recovery on quiet stars at the
     same S.
  3. Injection recovery on quiet stars drops by no more than 2 percentage points against prewhitening off.
  Failing any one blocks production.

## 3. Known-planet recovery test (new, pass/fail)

Every confirmed planet or active TOI (TFOPWG disposition not FP/FA) on a searched star with
expected S >= S* and at least 2 transits in the sector data must be recovered.

* Expected S = depth_exp x sqrt(n_tr) / CDPP_D, with n_tr the transits of the catalogue ephemeris that survive the
  v1.1 masks and CDPP_D our noise at the catalogue duration. depth_exp is the catalogue depth scaled by the
  contamination ratio of the aperture we search (target flux fraction of our light curve relative to the
  catalogue's). The ratio is recorded per star.
* Recovered means the reported peak period is within the period-grid plateau half-width of the catalogue period
  (`products/interim/p_grid_halfwidth_v1.csv`), or is a 2x or 1/2x alias and is flagged as one.
* Any miss is listed with its cause. A miss that is not explained by a recorded, pre-declared mechanism fails
  the test and blocks production.
* The clean v1.0 audit (`docs/v1.1_checks/known_planet_audit_clean_2026-11-11/`) is the before table.

## 8. Rulings of 2026-11-11 after code review (before any v1.1 sector 70 output)

These rulings were made after a code review of the validation code and before any v1.1 sector 70 null,
validation or production output existed. Where they differ from sections 2b and 3 they replace them.

### 8a. Prewhitening validation sample (dated exception to 2b)

* Two of the 25 Gaia DR3 stars (TIC 17228263 and TIC 279057510) are blinded holdout stars. They are dropped as a dated
  exception to "all 25 listed Gaia stars are kept", leaving 23 stars. The query and the list file are not edited.
* Every rate is reported with its n. With 23 stars one star moves the rate by about 4.3 points.

### 8b. Part one of the prewhitening pass rule (replaces the harmonic test in 2b)

* Most of these stars have no catalogued pulsation frequencies, so each star's frequency list is built from its own
  unfiltered sector 70 light curve (quality-masked, normalised): iterative prewhitening (Lomb-Scargle, highest peak
  first) down to an amplitude S/N of 4. The lists are frozen in a dated committed file before the filter runs.
* After filtering, the amplitude S/N is measured with Lomb-Scargle at every frozen frequency f_i. A star fails part one
  if any f_i has residual S/N above 4 (Breger's criterion), or if the BLS top peak frequency lies within one period-grid
  step of P = k/f_i for k = 1..20, or of a combination
  frequency |f_i +/- f_j| (and its k = 1..20 submultiples in period).
* Negative control: the same check on the unfiltered run must fail part one. If it does not, the test is invalid and the
  prewhitening validation fails.

### 8c. Part two (clarifies 2b)

* One-sided: only worse injection recovery on the pulsators than on quiet stars at the same expected S fails
  (pulsator minus quiet below -5 points).
* Expected-S bins with fewer than 5 stars are merged into a neighbour until every bin has at least 5. If a whole group
  (delta Scuti or gamma Dor) cannot reach 5 stars it is reported descriptively and excluded from pass/fail.
* The star is the variance unit: recovery is averaged per star first, and intervals are over stars, not injections.
* The quiet arm excludes the Gaia variables and known pulsators.

### 8d. Recovery threshold

* An injection or known planet counts as recovered only at S >= S* (the registered search threshold), not a fixed 10.

### 8e. Known-planet recovery test (replaces the exemptions in section 3)

* Contamination: our own aperture model is primary. The TIC contamination ratio is logged as a diagnostic and stars
  where the two differ by more than 20% are flagged. A star with no aperture value is ineligible, with the reason
  recorded. A factor of 1.0 is never assumed.
* Eligibility is computed before the run from the NASA Exoplanet Archive composite table (pscomppars) plus active TOIs:
  at least 2 transits in the data, expected S >= S*, not inside a declared mask, catalogue depth, duration and epoch
  present. The eligible list, with the reason for every ineligible planet, is written to a dated committed file before
  the run. No placeholder parameters are used.
* No excused misses: any eligible planet that is missed, for any reason including a runtime pipeline error, is a
  failure. Misses are diagnosed by cause but never excused.
* Recovery tolerance is the registered plateau half-width (exosearch/p_grid_halfwidth.py), with half a grid step only
  where that module itself falls back to it; 2x and 1/2x aliases are flagged and use the same tolerance.

## Amendment 2026-11-11: registered v1.1 scrambled-null transform

# Registered v1.1 Scrambled-Null Transform (Amendment)
**Date:** 2026-11-11  
**Status:** Post hoc Scientist ruling and revision; registered rule for v1.1. No rerun has been done yet.

---

## 1. Background & Root Cause Analysis

In the frozen v1.0.0 pipeline (`exosearch.nulltest.transform("scramble")`), the scrambled null test operated by cutting the quality-masked light curve into approximately 1-day blocks of cadences and permuting those blocks globally across the light curve before gap-edge trimming and detrending:

1. **Permutation across gaps:** Blocks were shuffled indiscriminately across data segments and spacecraft orbit gaps.
2. **Gap-edge ramp translocation:** Thermal ramps and scattered light features occurring immediately before and after orbit downlinks / data gaps were relocated into clean, unperturbed sections of the light curve.
3. **Step-edge artifacts:** Discontinuous edges between permuted blocks created artificial box-step dips.

As observed in Sector 106, this inflated the scrambled null test statistics ($S^*$), severely distorting the null distribution and interfering with the two-sample null comparison (TOST gate) against the flipped null.

---

## 2. Revised v1.1 Scramble Rule (Scientist Ruling 2026-11-11)

On 2026-11-11, the Scientist ruled to revise the segment rotation rule and supersede the earlier fallback proposal:

1. **Input light curve & gap-edge trimming:**
   The input is the quality-masked light curve ($Q = 0$, finite flux and errors). Before any scrambling occurs, `lightcurve.gap_edge_mask` is applied using the exact parameters of the detrender (`gap = 0.5` d, `trim = 0.3` d). All cadences within 0.3 d of gaps $> 0.5$ d or sector endpoints are dropped upfront so gap-edge ramps cannot enter the scrambling pool.

2. **Segmentation:**
   The remaining cadences are split into contiguous segments at all gaps $> 0.5$ d.

3. **Segment cyclic rotation:**
   Rotate **every** segment, regardless of length, by its own independent random cyclic integer offset drawn from `numpy.random.default_rng(seed)`:
   $$\text{offset}_i \sim \text{Uniform}\{0, N_i - 1\}$$
   Flux and flux error vectors move strictly together, time stamps stay fixed, and no sample crosses a gap boundary.

4. **Removal of fallback:**
   The Scientist ruling removes the block-shuffle fallback and the leave-unrotated path entirely. A 1-sample segment trivially rotates by 0. The configuration parameters `block_duration_multiplier` and `longest_trial_duration_d` have been deleted.

5. **Provenance recording:**
   The per-segment offsets and scheme (`scr_offsets`, `scr_scheme='segment_rotation'`, `n_segments`) are returned by `exosearch.v11.scramble.segment_rotate` and recorded in the v1.1 pipeline task output row.

6. **Configuration parameters:**
   The parameters in `configs/v1.1.json` under `"scramble"` are:
   - `gap_d`: $0.5$
   - `gap_trim_d`: $0.3$
   - `exclude_hosts_file`: per-sector path mapping to host exclusion tables (e.g. `"70": "configs/scramble_exclude_s0070_2026-11-11.csv"`).

---

## 3. Planted Signal Measurement & Conclusion

Using the real Sector 70 cadence and gap structure (`tests/fixtures/s0070_cadence.npz`), white noise plus mild red noise, and a box transit train injected at $P = 1.0, 3.0, 6.0$ d (each with raw unscrambled significance $> 20\sigma$), the phase-folded depth significance at injected $P/t_0$ after scrambling across 10 random seeds yielded:

```
P      median_sigma   max_sigma    n_seeds 
1.0    3.69           7.70         10      
3.0    1.82           7.23         10      
6.0    0.93           7.82         10      
```

### Conclusion Regarding Periodic Transit Preservation
With the real Sector 70 cadence (~8.3 d and ~10.9 d segments separated by a 4.01 d gap), cyclic rotation keeps the periodicity intact inside each segment. Consequently, cyclic rotation cannot be relied upon to erase real transits (max sigma stays above $3\sigma$ across seeds at every period, reaching up to $7.82\sigma$). This empirical result is accepted rather than tuned away. To prevent genuine planetary or eclipsing binary transits from polluting the scrambled null distribution, known hosts must be explicitly excluded.

---

## 4. Host Exclusion Rule

To ensure the scrambled null distribution is not contaminated by preserved coherent transits of known astrophysical systems, the pipeline implements **Host Exclusion**:
1. **Catalogues & Snapshots:**
   - **ExoFOP TOI Table:** Snapshot of 2026-11-10T21:05Z (all TOI hosts, any disposition).
   - **TESS Eclipsing Binaries:** Prsa et al. 2022 (VizieR J/ApJS/258/16, fetched 2026-11-10T22:58Z).
2. **Sector 70 Exclusion Table:**
   - Saved as a fixed list in `configs/scramble_exclude_s0070_2026-11-11.csv` (SHA256: `afa7c0122f3a1254177c87c85cbe7108acb9371c0b477dbf238615f03837cd97`).
   - Contains 285 unique TICs (222 TOI hosts, 67 TESS EBs, 4 overlapping).
   - Fixed list with strictly no runtime refresh.
3. **Pipeline Manifest Filtering:**
   - During manifest building (`exosearch.v11.run.build`), any TIC listed in the exclusion table has its `scramble_r*` tasks skipped. Real search and `invert` tasks for these TICs remain completely unchanged.
   - The exclusion file name and its SHA256 digest are recorded in the run provenance.

---

## 5. Status

This revision and host exclusion rule constitute a registered post hoc fix for the v1.1 pipeline dated 2026-11-11. No rerun has been done yet. v1.0.0 code (`exosearch/nulltest.py`) remains frozen byte-for-byte to maintain exact reproducibility of v1.0 products.
