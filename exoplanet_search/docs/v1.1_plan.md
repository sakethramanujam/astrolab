# v1.1 implementation plan (planning only; no v1.1 code or runs yet)

v1.0.0 stays frozen (config_hash 80ffc7f29943). v1.1 is a new pipeline version with its own config hash, nulls and
injections; nothing from v1.1 is mixed into v1.0 products or the interim layer. Findings behind each item:
`docs/v1.1_odd_even_secondary.md`.

## Statistic

1. **Exact box depth in S.** S from the box depth at each (P, D, T0) (compute_stats estimator), not the BLS
   fast-method depth; at minimum, refine the top-k fast peaks per star with the exact depth before taking the max.
2. **Out-of-transit term.** S normalised with sigma_D·sqrt(1 − D/P) restored, so white-noise S follows the
   joint-Gumbel calibration (N_eff ≈ 4.3e4 per star).
3. **Beta treatment inside the statistic**, chosen by the registered rule (`docs/preregistration/beta_treatment.md`);
   provisional choice c (floor at 1 − 2·sigma_beta), others as sensitivity rows.
4. **Pulsator prewhitening** before detrending: iterative sinusoid removal above ~5 c/d (stop at amplitude S/N < 4
   or 20 terms), frequencies and amplitudes logged per star; sigma_w measured after prewhitening.
   **Comb guard (RF Engineer):** before removing a peak at f, check the power at 2f and 3f. If the f, 2f, 3f
   amplitudes match the harmonic ladder of a box (periodic transit) of plausible duration (1–6 h at P = 1/f or an
   integer multiple), flag the peak as `comb` and do not remove it. Logged per star (`prewhiten_comb` flag).
5. **odd/even and secondary:** significance plus relative-depth rule (reject only when the difference is significant
   and > the registered fraction of the primary depth), validated on injections.
6. **Momentum-dump veto:** epochs within 0.1 d of a dump flagged; reject at ≤ 2 epochs, warn otherwise; N_tr recounted.

## Validation before any v1.1 re-search (injections only, then nulls; never candidates)

* **Prewhitening + comb guard on injections**, binned by duration and period, with USPs (P < 1 d) and 1–2 h
  durations broken out. Report recovery rate and recovered-depth bias (depth_rec/depth_inj) with and without
  prewhitening (and with the comb guard on/off). If prewhitening costs recovery or biases depth in any bin (USP
  harmonics fall above 5 c/d for P < 0.2 d; 1-h boxes put power near 24 c/d), lower the cutoff or protect transit
  harmonics, and re-validate. Uses the v1.0 injection hosts and seeds on S70 (re-injected, v1.1 code).
* Beta treatment selected on the v1.0 interim nulls (flipped + scrambled r0) and injections.
* Every headline number (S*, completeness, false-alarm rate, candidate counts) reported with and without the
  star-quality cut, on the site and in the docs.

## Runs (after validation; launch decision and compute allocation by the owner)

Fresh v1.1 nulls at the registered sizes (`docs/preregistration/s_star_freeze.md`: full flipped + 3 scrambled per
sector, S70 and S106), v1.1 injections (same spec as injection_v1), then the v1.1 real re-search. Frozen S* comes
from these only.

## Multi-host execution

* Extra workers (an 18-core ARM machine and an x86 Linux machine) run the same float64 CPU code at the **pinned v1.1
  commit** with a **lockfile** (exact package versions, same BLAS threading = 1).
* **Split by TIC ID**: each star's real, null and injection runs stay on one host.
* **Gate before any merge:** a shared batch of ~200 stars run on every host must give the same best (P, D) and S
  equal to within 1e-6 (absolute) across hosts. Any failure blocks the merge for that host.
* Rows carry an opaque `host_id` (h1, h2, h3), `arch` and `lib_versions`; never real hostnames. The host_id mapping
  lives outside the repo.
* GPU or float32 BLS is a **separate statistic** with its own nulls and injections, never mixed into S*.

## Compute and ETA

The lane cap (`docs/interim_lane_cap.md`) frees 3 cores when labels finish (~20:30 PST Nov 10; the queued S105
null and S70 real subsamples take them first, ~5 h), 3 more when injection run 1 for S70 ends (~22:30 PST), and 6
when scrambled r0 ends (~05:00 PST Nov 11). From then 12 batch cores are free. At v1.0 throughput (~12 stars/min per
worker) a v1.1 flipped null for S70 + S106 (25.8k stars) takes ~3 h on 12 cores, three scrambled realizations ~9 h,
12k injections ~1.5 h, so ~14 h of runs once v1.1 code and the injection validation (~1 day) are done: earliest
frozen S* around Nov 13, subject to the owner's compute decision and any extra hosts passing the gate.

## Registered duration-grid cap (physical duty-cycle limit)

* Per star, cap the trial durations at a maximum duty cycle q_max(P, rho_*) = 3 × the circular, central-transit
  duty cycle from the TIC density: q_circ = T14/P ≈ (1/π)·(3π / (G·rho_* ·P²))^(1/3) (for b = 0, Rp ≪ R_*),
  so D_max(P) = 3·q_circ·P. Stars without a TIC density get q ≤ 0.1. Following Hippke & Heller (2019, A&A 623, A39;
  TLS), which grids durations by the stellar density.
* Applied identically to the real search, the nulls and the injections (same function, same TIC inputs).
* Consequence: fewer independent trials, so the white-noise N_eff (≈ 4.3e4 per star in v1.0) and the white-noise S*
  drop; both are re-derived for v1.1 rather than carried over.
* Expected effect on the depth audit: the D/P 0.2–0.6 null rows (2,151 of the S70 flipped null; 3.6% with
  `depth_box`/`depth` > 2× or `depth` ≤ 0, p90 1.30) are mostly short-P/long-D boxes that no star of typical density
  can produce (q_circ ≈ 0.03–0.1 for main-sequence stars at P = 0.5–3 d, so 3·q_circ ≲ 0.3). Most of them fall outside
  the capped grid; the remainder are giants/low-density stars, where long boxes stay allowed.
* **Injection design for wrong densities.** A registered subset of injections (≥ 20%) draws the transit from
  "true" stellar parameters that differ from TIC while the grid is still capped with the TIC value: unresolved
  binaries (radius inflated, density overestimated), misclassified subgiants (true density ~3–10× below TIC), and
  density errors spread log-uniformly up to and beyond 27× (duration factor ≥ 3, i.e. beyond the margin). Reported
  completeness includes these wrong-density losses, broken out by density-error factor.
